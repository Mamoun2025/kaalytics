## Les outils, et comment s'en servir

```bash
python3 -m scripts.seo.gen_head       # regenere le <head> de toutes les pages du catalogue
python3 -m scripts.seo.gen_head --dry-run --only <page>   # simulation, n'ecrit rien
python3 -m scripts.seo.links          # canonise les liens internes
python3 -m scripts.seo.gen_sitemap --lastmod AAAA-MM-JJ
python3 -m scripts.seo.check_seo      # verificateur, code de sortie 1 si violation
python3 -m pytest tests/seo -v
```

**Règle de travail** : après toute modification de `data/seo/*.json` ou d'une page,
relancer `gen_head`, puis `gen_sitemap`, puis `check_seo`. Le vérificateur refuse un
sitemap désynchronisé du catalogue.

## À reprendre en P2

**Contenu — c'est le cœur de P2 :**

- Les 6 pages `industries/` sont encore celles héritées de FleetOps (BTP, transport, mines,
  location, industrie, distribution). Elles doivent être refondues sur les secteurs réels du
  portefeuille : Excelsa, Multiprobat, ATClimatisation, Transwin, KEvents, InternationalDealer.
- Les 3 études de cas fictives (`locamat`, `terrafleet`, `transmaroc`) attendent d'être
  réécrites avec de vrais chiffres anonymisés. Elles portent un champ `_note` daté.
- La couche ERP (`/erp/` + une page par ERP : Odoo, Cegid, Sage, SAP, Dynamics) n'existe pas
  encore. C'est la transposition des pages-marques de BEKS, et le principal gisement de
  requêtes qualifiées.
- Les pages font 400 à 700 mots ; la cible du gabarit est ~1 800.

**Points techniques différés :**

- **6 titres dépassent 70 caractères** et seront tronqués dans les résultats Google :
  `products/daedalia` (83), `modules/sales-intelligence` (73 FR / 71 EN),
  `modules/financial-operations` (72), `modules/supply-chain` (73),
  `en/modules/digital-platform` (74). À reprendre avec la réécriture éditoriale.
- **Le second système i18n** (`assets/js/i18n/i18n.js`, attributs `data-i18n`, bascule
  `?lang=`) n'a pas été retiré : la spec le place en P2. Il coexiste avec le système par
  chemin `/en/` sans que rien ne dise lequel fait autorité.
- Les tests ne fonctionnent que lancés via `python3 -m pytest` — le `-m` met la racine sur
  `sys.path`. Un `conftest.py` à la racine réglerait le cas d'un `pytest` nu.
- `head.py` n'échappe pas `lang`, `url` et `canonical`. Sans risque aujourd'hui, les données
  étant contrôlées.
- `htmlio.py` ne reconnaît `</head>` qu'en minuscules. Toutes les pages du site le sont.
- `test_hreflang_reciproque_et_pas_darabe` porte un nom trompeur : il ne teste que l'absence
  d'arabe. À renommer.

**Mesure — bloquée sur des valeurs externes :**

La tâche 12 du plan P1 n'a pas été exécutée. Elle attend deux choses que seul Mamoun peut
fournir : l'identifiant GA4 réel (le code contient encore le placeholder littéral
`G-XXXXXXXXXX`) et le mode de vérification Search Console. Elle couvre aussi la clé IndexNow
et le workflow GitHub de notification à Bing et Yandex. Sans elle, aucune donnée
d'indexation ni de requêtes n'est disponible.

## Ce que le chantier a appris

Trois défauts ont échappé aux tests et n'ont été trouvés que par relecture ou audit externe :
l'indentation cassée par les expressions de nettoyage, le français désaccentué dans tout le
catalogue, et 10 pages anglaises livrées avec un corps français. Les tests étaient verts dans
les trois cas.

D'où la règle adoptée en cours de route, à conserver : **vérifier l'état réel du site entier
après chaque étape, pas seulement les tests de l'étape.** C'est ce que fait désormais
`check_seo.py`, dont les 24 règles ont toutes été prouvées falsifiables par injection de
défaut.
